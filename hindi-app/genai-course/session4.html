Session 04 · 30 min

Prompt Engineering & Injection

A repeatable prompt structure, when chain-of-thought helps, how prompt injection works, and how to keep PII and API keys out of harm's way.

1 · Context is king

Role-based prompting and the CLEAR framework

A model can only be as precise as the brief you give it. Five ingredients turn a vague request into a reliable one.

IngredientExample
Context"This is for a SaaS company handling financial data."
Logic"Think step by step before answering."
Explicitness"Explain OAuth 2.0 for backend engineers in under 150 words."
Alignment"Do not expose secrets or real tokens."
Response format"Bullet points with one real-world example."
Many frameworks, one ideaYou will see acronyms such as RACE, CARE, APE, ROSES, CREATE, TAG, COAST, PAIN, RISE and CREO. They all re-package the same five ingredients: who the model is, what it knows, what to do, within which limits, in what shape. Learn the ingredients, not the acronyms.
2 · The Gold Prompt

One template that covers most real work

Role:           You are an expert in <domain>.
Context:        <relevant background information>
Task:           <clear and specific instruction>
Constraints:    <any limits or rules>
Output Format:  <exact structure required>
Try it · 5 minRewrite your most-used prompt into the five slots. Run both versions side by side. Count how many follow-up messages each one needed.

"Chain-of-Thought turns LLMs from guessers into reasoners."
CoT helpsMaths / logicSystem designSecurity analysis
CoT adds littleFact lookupSummarisation
Class demoIf a train leaves City A at 9 AM at 60 km/h and another leaves City B at 10 AM at 80 km/h, which reaches first?
Ask plainly, then add "think step by step". Notice that the second answer asks for the missing distance instead of guessing. That is the value of reasoning: it surfaces what is under-specified.

Decomposition

Break big tasks into smaller prompts. "Write the report" becomes outline → section drafts → consistency pass → executive summary. Each step is easier to verify and cheaper to retry.

4 · Prompt injection

When input becomes instruction

Prompt injection happens when user input overrides or manipulates the system instructions, causing the model to leak internal prompts, ignore safety rules, expose sensitive data or perform unintended actions. The root cause: the model treats everything in its context as potential instruction.

The "grandmother" trickWrapping a forbidden request in a role-play ("my late grandmother used to read me…") to slip past refusals.
JailbreaksLong preambles that "pump up" the model into a persona with no rules.
The $1 carA dealership chatbot talked into agreeing to sell a vehicle for a dollar, "no takesies backsies". A real incident and a real lesson about giving bots authority.
Defence principleTreat user input as data, not instructions. Separate it clearly, validate outputs, never give the model authority it does not need, and assume any text it reads (web pages, documents, emails) can contain an attack.
5 · Data protection

Keeping PII out of the model

LLMs remember context during a session, may log inputs for debugging, and can accidentally leak data in responses. So:

Mask or remove sensitive data before sending

Original: "My Aadhaar is 123456789012"
To LLM:   "My Aadhaar is XXXXXXXXXXXX"

Use data classification

Tag data as PublicInternalConfidentialRestricted. Models should receive only Public or sanitised Internal data.

Post-processing redactionScan model output for email patterns, long numbers, patient IDs. Redact before showing users.
Zero-retention APIsPrefer providers that offer no training on your data and short-lived logs.
"If you don't need the data for reasoning, don't send it to the model."

Practitioner note: for analytics on HR records in a client engagement, we generated fully synthetic data with the same statistical shape rather than sending a single real record to a model.

6 · Secrets

Safe API key management

AI API keys are high-value secrets: they spend your money and can expose your data.

MistakeHard-coding keys in source code.
MistakeCommitting keys to Git, even once.
MistakeExposing keys in frontend apps where anyone can read them.

Do instead: keep keys in environment variables or a secrets manager, call providers from a backend you control, rotate keys on a schedule, set spend limits, and scan repositories for leaked secrets in CI.

Homework · 20 minBuild a one-page "AI usage policy" for your team: what data may be pasted into public tools, which tools are approved, and who owns the API keys.
